# API reference

Base path `/api/rag`. Every endpoint requires `Authorization: Bearer <jwt>`, signed with
`JWT_SECRET`. Setting `AUTH_DISABLED=1` bypasses this for local work only.

All request and response bodies are JSON, UTF-8. Question and answer text is Arabic.

---

## POST /api/rag/ask

Retrieve, ground, generate. The production path.

**Request**

| Field | Type | Required | Description |
|---|---|---|---|
| `question` | string | yes | The student's question, in Arabic, French or Darja |
| `subject` | string | no | Must match `subjects.name` exactly. Defaults to `RAG_DEFAULT_SUBJECT` |
| `mastery` | number | no | Predicted mastery for this lesson section, from `POST /api/dkt/weakest` or `/predict`. Accepts 0–1 or 0–100. Selects a difficulty tier; omitting it leaves the prompt unadapted |
| `debugIncludeContext` | boolean | no | Return the assembled prompt context. Off by default: that context is paid course material |

```bash
curl -X POST http://localhost:5001/api/rag/ask \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"question":"ما هي مظاهر الصراع بين المعسكرين؟","subject":"التاريخ والجغرافيا","mastery":0.34}'
```

**Response**

```json
{
  "answer": "تجلى الصراع بين المعسكرين في عدة مظاهر…",
  "sources": [
    {
      "courseId": 1,
      "coursePartId": 149,
      "courseTitle": "الدرس الأول: تطور العالم في ظل الثنائية القطبية",
      "sectionTitle": "مظاهر الصراع بين المعسكرين",
      "category": "history",
      "relevanceScore": 0.71
    }
  ],
  "answerMode": "grounded",
  "languageRegister": "msa",
  "difficulty": { "tier": "foundational", "mastery": 0.34 },
  "citationCheck": { "ok": true, "unverified": [] },
  "confidence": "high",
  "chunksUsed": 3
}
```

| Field | Description |
|---|---|
| `answer` | Generated text. Empty string when the generator is out of quota |
| `sources` | Citations, ordered by relevance. `relevanceScore` is cosine in (0,1) from the semantic path, or a small integer from the keyword path |
| `sources[].coursePartId` | The lesson section, and the knowledge tracer's micro-skill key. Send it to `/api/dkt/*`; `null` on pre-migration lessons |
| `answerMode` | `grounded`, `knowledge_fallback`, `no_match`, `rejected`, or `fallback` (see below) |
| `languageRegister` | Detected register of the question: `msa`, `french`, `darja` or `mixed`. Reported, so a client can log what students actually type |
| `difficulty` | Present only when `mastery` was sent. The tier the prompt was steered to |
| `citationCheck` | Grounded answers only. `ok: false` means the answer cited a section that was not retrieved — a fabricated source. Reported, never silently repaired |
| `confidence` | `high` / `medium` / `low`, derived from the mode and the chunk count |
| `chunksUsed` | Chunks placed in the prompt |
| `context` | Present only when `debugIncludeContext` is true |

**Answer modes.** The mode is not decoration: it states which regime produced the text, and a client
should surface the distinction to the student.

| `answerMode` | Meaning |
|---|---|
| `grounded` | Retrieval was strong. The answer is constrained to the retrieved lessons |
| `knowledge_fallback` | Retrieval was weak but the question is curricular. Answered from model knowledge; the answer itself opens by saying so |
| `no_match` | Retrieval was weak and the question is off-syllabus. A static refusal — no model was called |
| `rejected` | The question contained an instruction aimed at the system rather than a curriculum question. Refused before retrieval, so it cost no embedding and no generation call. `rejectionReason` names the pattern |
| `fallback` | The generator was unavailable (quota). `answer` is empty and `_error` explains |

**Status codes**

| Code | Condition |
|---|---|
| 200 | Includes `no_match` refusals and quota-exhausted responses |
| 400 | `question` missing or blank |
| 401 | Token missing or invalid |
| 503 | `LLM_API_KEY` not configured |
| 500 | Generation failed for any other reason |

The quota case answers 200 deliberately. It is an operational condition, not a client error, and a
200 with an empty answer lets a client degrade to plain chat instead of showing a failure.

## POST /api/rag/ask-local

Identical retrieval, generated by a locally served OpenAI-compatible model
(`LOCAL_OPENAI_BASE_URL`) — a small self-hosted model in place of the hosted one.

Differences from `/ask`:

- Retrieves `RAG_TOP_K_LOCAL` chunks (default 3) instead of 5.
- Caps output at `LOCAL_MAX_TOKENS` (default 350); latency on a single GPU scales with output length.
- **No knowledge-fallback mode.** Empty retrieval returns `no_match`. A small fine-tuned model
  operating outside its retrieved context is exactly the failure this system exists to avoid.

## GET /api/rag/subjects

Subjects with at least one indexed chunk, so a client never offers a subject that would answer
everything with `no_match`.

```json
[{ "id": 1, "name": "التاريخ والجغرافيا", "icon": "📚", "color": "#6f42c1" }]
```

---

## GET /api/rag/stats?subject=...

Corpus statistics for one subject.

```json
{
  "subject": "التاريخ والجغرافيا",
  "total_courses": 13,
  "total_chunks": 44,
  "avg_chunk_size": 1423,
  "min_chunk_size": 234,
  "max_chunk_size": 4102
}
```

The length distribution is the operationally useful part: it predicts how much of the prompt budget
a single retrieved chunk will consume, and how often per-chunk truncation will fire.

Returns 404 when the subject name does not exist.

## GET /api/health

Unauthenticated. Reports each dependency separately, so a failure names the component at fault.

```json
{
  "status": "OK",
  "database": { "ok": true, "database": "deepbac", "via": "tcp" },
  "retrieval": "qdrant+embeddings",
  "qdrantCollection": "bac_rag_chunks",
  "vectorSize": 1024,
  "generator": "deepseek-chat"
}
```

`status` is `DEGRADED` when MySQL is unreachable. `retrieval` reads `keyword-only` when semantic
search is unconfigured — the service still answers in that state, which is why it is reported rather
than treated as an error.

---

## Rate limiting

200 requests per 15 minutes per address by default (`RATE_LIMIT_MAX`), tighter than a normal CRUD
API because each answer spends an embedding call and a generation call. Set `TRUST_PROXY_HOPS` to
the real number of reverse proxies: too low and the proxy throttles itself, too high and a caller
can spoof its address.

## Composing with the knowledge tracer

The two services never call each other — see [ARCHITECTURE.md](ARCHITECTURE.md) §Two services for
why — so the client makes both calls. The whole integration is two requests and one field:

```bash
# 1. Which section is weakest, and how weak?
curl -s -X POST http://localhost:5002/api/dkt/weakest \
  -H 'Content-Type: application/json' -H "Authorization: Bearer $TOKEN" \
  -d '{"history":[{"course_part_id":149,"score":40,"response_time_ms":9000},
                  {"course_part_id":149,"score":25,"response_time_ms":12000}],"top_n":1}'
# → { "weakest": [ { "course_part_id": 149, "predicted_normalized": 0.34, … } ] }

# 2. Explain it, steered to that mastery level.
curl -s -X POST http://localhost:5001/api/rag/ask \
  -H 'Content-Type: application/json' -H "Authorization: Bearer $TOKEN" \
  -d '{"question":"اشرح لي مظاهر الصراع بين المعسكرين","mastery":0.34}'
# → an answer in the foundational tier, citing coursePartId 149
```

One token authenticates both. `course_part_id` and `coursePartId` are the same key, which is what
makes the round trip work without a mapping layer: the section the tracer names is the section the
retriever indexes. The DKT endpoints are documented in [DKT_API.md](DKT_API.md).

Sending `mastery` is optional at every step. A client that skips the first request gets an
unadapted answer, not an error.
